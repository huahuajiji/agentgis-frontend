# 项目评价

> 更新于 2026-11-26，对应持久化（IndexedDB）+ 手动后端同步 + 属性表完成后的状态。

## 简短结论

AgentGIS 是一个扎实的 GIS 地图文档编辑器前端。它有类型化的地图文档模型、真实的撤销/重做、操作压缩、GeoJSON 流程、高德地图绘制编辑集成。

前端已经收敛：界面上不存在「点了没反应」的控件，导航从 6 个区收到 3 个，占位面板全部移除。它现在是一个**小而完整**的原型，而不是**看起来很大但走不通**的半成品。核心模块已由 98 个 Vitest 用例覆盖，持久化走 IndexedDB，并接上了后端文档 CRUD 的手动同步。

前端原型已经成形，剩下的是部署与空间分析。

## 优点

- **数据模型先行**：Zod schema 是单一真相源，7 种 typed operation 覆盖全部变更；这是全项目最值钱的资产。
- **操作式架构正确**：撤销/重做双栈（打包进池后不可撤销）、commit 池待同步队列、外部操作审核记录，为 AI 接入预留了干净的接口。
- **编排与计算分离**：store 只做编排，14 个纯函数模块承担计算——正是这批模块最先获得了单测覆盖（98 例全绿），替换持久化层有测试兜底。
- **地图集成边界清晰**：高德加载、绘制会话、编辑会话、要素适配器与通用应用壳完全隔离。
- **BYOK 姿态正确**：仓库不含凭据。
- **双端共用一套状态**：单一状态源，桌面工作台不复制逻辑。
- **界面可信**：收敛后 3 区导航、3 个真面板、2 个真页签，运行时占位块为 0。

## 风险

- **测试只覆盖纯函数与适配层**：核心模块已有 98 例单测（含 fetch mock）；组件层（Shell、检查器、地图会话）仍无测试，回归主要靠手动过流程。
- ~~没有后端~~：已接 FastAPI 文档 CRUD（手动同步），换设备可通过「从云端拉取」恢复；暂无协作能力。
- **没有部署**：没有可访问链接，作品集价值无法兑现。（部署阶段解决）
- **凭据存在 localStorage**：原型可接受，公开部署前应改用演示 Key + 域名白名单。
- ~~无 LICENSE~~：已补 MIT（2026-11-26）。
- **高德行为依赖外部凭据与网络环境**：demo 需要在目标用户相近的网络环境验证。
- ~~移动端未同步收敛~~：移动端已于 2026-11-20 整体移除，此风险消除。

## 评分

| 维度 | 评价 |
|---|---|
| 架构设计 | 强：数据模型与分层是同类学生项目里的上游水平 |
| 完成度 | 中：单机业务线基本可用，缺持久化闭环 |
| 工程化 | 中：构建、类型检查、核心模块单测到位；缺 CI 与部署 |
| 作品集可用性 | 待兑现：需要阶段 3–4 完成才有对外链接 |

底线判断：这是一个**值得走完**的项目，因为它缺的都是可以补的工程项，而它的设计底子不是靠补能补出来的。
