# 项目评价

> 更新于 2026-11-18，对应前端收敛后的状态。

## 简短结论

AgentGIS 是一个扎实的 GIS 地图文档编辑器前端。它有类型化的地图文档模型、真实的撤销/重做、操作压缩、GeoJSON 流程、高德地图绘制编辑集成，以及一套与桌面端共用状态模型的移动端工作流。

前端已经收敛：界面上不存在「点了没反应」的控件，导航从 6 个区收到 3 个，占位面板全部移除。它现在是一个**小而完整**的原型，而不是**看起来很大但走不通**的半成品。

仍然要明确：它是前端原型，没有后端、没有测试、没有部署。离"作品集主项目"还差三个阶段（测试、后端、部署）。

## 优点

- **数据模型先行**：Zod schema 是单一真相源，7 种 typed operation 覆盖全部变更；这是全项目最值钱的资产。
- **操作式架构正确**：撤销/重做双栈、提交历史、外部操作审核记录，为 AI 接入预留了干净的接口。
- **编排与计算分离**：store 只做编排，14 个纯函数模块承担计算——这正是这些模块最该、也最容易补测试的地方。
- **地图集成边界清晰**：高德加载、绘制会话、编辑会话、要素适配器与通用应用壳完全隔离。
- **BYOK 姿态正确**：仓库不含凭据。
- **双端共用一套状态**：桌面工作台与移动四 tab 不复制逻辑。
- **界面可信**：收敛后 3 区导航、3 个真面板、2 个真页签，运行时占位块为 0。

## 风险

- **没有自动化测试**：`shared/mapDocument/*` 的操作压缩、撤销重做、GeoJSON 收发都该有单测；阶段 3 替换持久化层时这是最大的风险点。（阶段 2 解决）
- **没有后端**：仅 localStorage，换浏览器即丢；无法证明持久化与协作能力。（阶段 3 解决）
- **没有部署**：没有可访问链接，作品集价值无法兑现。（阶段 4 解决）
- **凭据存在 localStorage**：原型可接受，公开部署前应改用演示 Key + 域名白名单。
- **无 LICENSE**：公开前必须补充。
- **高德行为依赖外部凭据与网络环境**：demo 需要在目标用户相近的网络环境验证。
- **移动端未同步收敛**：`MobileShell` 仍保留"参考图层"相关文案，与桌面端三区结构不完全一致。

## 建议下一步（与路线图一致）

1. Vitest 单测：撤销/重做、操作压缩、GeoJSON 收发（约 15–25 个用例）。
2. FastAPI 后端：文档持久化（替换 localStorage）+ 空间分析两算子（buffer / overlay）。
3. 部署：前端静态托管（hash 路由 + base 配置）+ 后端容器，产出可访问链接。
4. 补 LICENSE、演示数据、作品集截图。
5. 可选：自然语言 → MapOperation 的 AI 薄接口。

## 评分

| 维度 | 评价 |
|---|---|
| 架构设计 | 强：数据模型与分层是同类学生项目里的上游水平 |
| 完成度 | 中：单机业务线基本可用，缺持久化闭环 |
| 工程化 | 弱→中：构建与类型检查到位，但无测试、无 CI、无部署 |
| 作品集可用性 | 待兑现：需要阶段 3–4 完成才有对外链接 |

底线判断：这是一个**值得走完**的项目，因为它缺的都是可以补的工程项，而它的设计底子不是靠补能补出来的。
